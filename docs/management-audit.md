# 公开赛、班级和孩子管理验收记录

日期：2026-10-17。目标：正式站点 /app。测试使用独立 SQLite 数据目录和本地测试账号，不向真实用户发送消息或对战邀请。

## 已验证的流程

- 公开匹配：七种用时、同用时匹配、排队状态、取消、刷新恢复、队列超时、双方进入同一房间、正确黑白方、实际走棋和结束。
- 教师：创建班级、读取邀请码、发布公告、编辑棋盘作业、保留编辑内容、验证局面和标准答案、查看每个学生的作业完成情况。
- 学生：邀请码加入、重复加入提示、公告、作业棋盘、提交答案、正确/错误反馈、截止限制、刷新留在班级页面。
- 家长：绑定码刷新/过期/使用后失效、绑定孩子、孩子的答题/对战/作业记录、孩子所在班级和本人孩子的完成进度。
- 学习计划：创建/编辑/删除、整数和合法日期校验、起止顺序、刷新保留、孩子首页展示当前有效计划。
- 周报：按语言缓存、历史报告、完整统计持久化、UTC周期一致、正确展示本周与累计统计。
- 多语言：中、英、日、法、西语管理文案；用户自行填写的名字、公告和作业标题保持原文。
- 权限：未绑定家长不能看孩子，其他班级教师不能布置作业或查看进度，家长仅看自己绑定孩子的进度，学生不能获得标准答案，不能跨班提交作业，旧公告/任务接口要求本班教师。

## 修复的关键问题

1. 公开赛仅返回第二人的匹配结果、错误白方标记、没有排队页面/恢复/退出。
2. 学生班级页面没有作业提交入口，教师没有逐人进度。
3. 作业答案在学生接口泄露，提交作业未核对所属班级，旧发布接口缺班级权限。
4. 家长的孩子详情只有概要；计划只能创建；空请求格式导致删除/绑定码刷新失败。
5. 周报部分统计字段没有写入 SQLite，语言缓存混用，生成提示强制中文。
6. 教师更换编辑棋子会清空标题/答案，建班后靠固定延迟选择班级。
7. 管理页面中文硬编码、手机控件缺标签及换行问题。

## 明确未实现的业务范围

- 当前公开赛是公开匹配，不是有报名、分组、轮次、积分配对或淘汰赛程的完整赛事系统。
- 短信代码目前用于验证码，没有家长事件通知的触发规则、通知模板或发送记录；本次没有发送真实短信。
- 尚未定义孩子解绑/移除学生的业务规则，本次没有增加这些破坏关联的操作。
- 当前应用以单个后端实例运行；排队状态在内存，重启需重新排队，已匹配房间持久化。没有验证多实例负载均衡与高并发容量。
- 自动生成评语的真实千问输出依赖生产模型可用性；本次浏览器测试使用隔离环境的回退评语，不对真实孩子发起模型测试。
